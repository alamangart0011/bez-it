# Этап 7. Единый центр администратора и cleanup

Что закрыто:
- отдельная административная вкладка в том же shell, без отдельного чужого интерфейса;
- пользователи: смена роли, статуса, активности, завершение всех сессий;
- приглашения: генерация рабочих invite-ссылок;
- комнаты: создание, архивация, владелец, участники, модераторы;
- отделы: создание с автоматическим выпуском базовых комнат;
- система: название продукта, организация, ИНН, лицензионный пакет, поддержка;
- cleanup: архивирование комнат вместо хаотичного удаления, системные параметры вынесены в `system_settings`.

Что важно для existing baseline:
1. Применить `infra/sql/003_stage7_admin_center.sql`, если БД уже существует.
2. После этого обновить backend и frontend.
3. Проверить:
   - `/api/admin/overview`
   - `/api/admin/system`
   - создание отдела
   - создание комнаты
   - завершение сессий сотрудника

Цель этапа:
администратор получает полноценный центр управления, но обычный рабочий контур сотрудников не ломается и не подменяется отдельной админской системой.

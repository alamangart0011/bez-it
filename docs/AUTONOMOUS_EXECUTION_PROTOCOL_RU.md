# Autonomous execution protocol — room-based V17

## Правило итерации
После каждого полезного действия:
1. кратко фиксировать, что сделано
2. кратко фиксировать, что будет делаться дальше
3. не менять baseline
4. при изменении реального состояния пересматривать проценты
5. дописывать execution ledger, если изменился источник истины

## Что считать полезным действием
- новый source-of-truth файл
- новый acceptance/runbook/backlog файл
- новый smoke/script
- новый факт browser acceptance
- новый факт live runtime
- новый P0 defect с точным сценарием воспроизведения
- новый cleanup-факт по shell/admin/rooms/voice/meeting

## Что не считать полезным действием
- повторение уже зафиксированного статуса
- новый разгон с нуля
- новый product pivot
- новый параллельный active contour

## Формат краткого статуса
- сделано: ...
- дальше: ...
- общий процент: ...
- по ключевому этапу: ...

## Правило процентов
- проценты меняются только после реального нового факта
- новые документы сами по себе не повышают runtime-процент
- browser acceptance и cleanup повышают проценты только после фактического прохождения или внедрения

# Jino 443 blocker checklist

## Что уже подтверждено
- public HTTP on `ai.voice.oboron-it.ru` is alive
- `/api/health` over HTTP returns 200
- TCP 80 is open
- TCP 443 is still closed

## Что это означает
Проблема больше не в VPS, docker, nginx или приложении.
Проблема находится на внешнем уровне Jino proxy / IP binding / HTTPS publication.

## Что проверить в панели Jino
1. Проксирование HTTP(S) должно быть включено именно на IPv4 `81.177.141.214`, потому что домен `ai.voice.oboron-it.ru` указывает на этот IP.
2. Если галочка была поставлена на другом IPv4, это не поможет домену.
3. Внешние порты должны включать `80` и `443`.
4. Внутренний порт должен быть `80`.
5. Если в панели есть кнопка применения/пересоздания правила, её нужно выполнить.
6. Если есть отдельное правило для 443, оно должно указывать на тот же VPS и тот же внутренний порт 80.

## Признак успеха
- `bash scripts/jino_proxy_probe.sh` показывает `80=open` и `443=open`
- `bash scripts/jino_https_smoke.sh` перестаёт падать на connect refused

## Если 443 всё равно закрыт
Нужно открыть обращение в поддержку Jino: внешний 443 для домена не публикуется, несмотря на включённое HTTP(S) proxy на нужном IP.

# Screen acceptance matrix — room-based V17

## 1. Shell

### Обязательное
- shell открывается сразу после логина
- левый room tree виден
- правый контекст не ломает layout
- нет пустого центрального экрана

### Критерий приёмки
- пользователь попадает в рабочую оболочку без технического шума и без пустого состояния

---

## 2. Dashboard / главная

### Обязательное
- активные комнаты
- голосовые сейчас
- собрания
- заявки / инциденты / быстрые переходы

### Критерий приёмки
- главная работает как диспетчерская, а не как self-description сборки

---

## 3. Текстовая комната

### Обязательное
- room header
- feed сообщений
- composer
- right context
- участники / файлы / закрепы

### Критерий приёмки
- сообщение отправляется и читается после reload
- нет тяжёлого визуального мусора в центре

---

## 4. Голосовая комната

### Обязательное
- список участников
- кнопка входа в голос
- локальное voice state
- moderator path
- queue / summon / move user при наличии роли

### Критерий приёмки
- voice screen понятен сотруднику и полезен модератору

---

## 5. Комната собрания

### Обязательное
- статус собрания
- ведущий
- участники
- повестка
- материалы
- журнал
- итог

### Критерий приёмки
- meeting room читается как отдельный сценарий работы

---

## 6. Profile

### Обязательное
- роль
- статус
- отдел
- контактные данные
- completion state

### Критерий приёмки
- профиль не выглядит черновиком и не валит личный контур

---

## 7. Settings

### Обязательное
- интерфейс
- уведомления
- голос
- доступность

### Критерий приёмки
- настройки компактны и пригодны для реальной работы

---

## 8. Admin overview

### Обязательное
- live runtime summary
- users summary
- rooms summary
- incidents / operator summary
- быстрые переходы

### Критерий приёмки
- overview не валится целиком из-за одного widget

---

## 9. Admin users

### Обязательное
- список пользователей
- роль
- статус
- отдел
- быстрые действия

### Критерий приёмки
- users screen не превращён в длинную форму и не даёт 500 при частично пустых данных

---

## 10. Admin rooms

### Обязательное
- список комнат
- тип комнаты
- архивный статус
- room actions

### Критерий приёмки
- архив и active rooms разделены логически
- тестовый мусор не мешает обычной работе

---

## 11. Admin departments

### Обязательное
- список отделов
- связанные сотрудники
- связанные комнаты

### Критерий приёмки
- departments screen не пустой и не выглядит незавершённым

---

## 12. Admin invitations

### Обязательное
- список приглашений
- статус
- создание приглашения

### Критерий приёмки
- invitation flow не тестовый и не даёт 500 на пустой таблице

---

## 13. Admin sessions

### Обязательное
- список сессий
- завершение сессии
- завершение всех сессий пользователя

### Критерий приёмки
- session control работает как часть security-контура

---

## 14. Admin system

### Обязательное
- бренд
- системные настройки
- организационные реквизиты
- release/system defaults

### Критерий приёмки
- system screen не зависит от заранее заполненной таблицы и умеет жить на safe defaults

---

## 15. Admin audit

### Обязательное
- фильтры
- actor / action / result
- drill-down по записи

### Критерий приёмки
- аудит читается как рабочий контрольный журнал, а не как текстовая простыня

---

## Общий критерий

Экран считается принятым, если он:
- открывается без критического 500
- не пустой
- не заполнен техническим шумом
- не ломает room-based логику
- выполняет минимальный рабочий сценарий своей роли

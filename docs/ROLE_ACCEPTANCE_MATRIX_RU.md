# Role acceptance matrix — room-based V17

## Супер-администратор

### Обязательные сценарии
- вход в систему
- открытие shell
- открытие admin center
- users / rooms / departments / invitations / sessions / system / audit / incidents
- изменение системных настроек
- просмотр операторского overview

### Критерий приёмки
- весь admin center открывается без критического фейла
- один проблемный widget не валит экран целиком
- системные настройки управляемы

---

## Администратор

### Обязательные сценарии
- вход в систему
- открыть users
- открыть rooms
- создать / архивировать комнату
- открыть invitations
- открыть sessions
- открыть audit
- выполнить базовые operator actions

### Критерий приёмки
- администратор управляет системой из одного центра
- обычный runtime не зашумлён его служебными действиями

---

## Руководитель / ведущий

### Обязательные сценарии
- войти в shell
- открыть voice room
- войти в голос
- открыть meeting room
- увидеть участников
- подтвердить вход по запросу
- вызвать пользователя в комнату
- запустить / завершить собрание

### Критерий приёмки
- voice и meeting работают как инструмент управления командой
- руководитель не теряется в интерфейсе

---

## Модератор

### Обязательные сценарии
- открыть voice room
- увидеть очередь входа
- одобрить / отклонить заявку
- mute / deafen / remove
- быстро снять локальный инцидент в комнате

### Критерий приёмки
- dangerous actions доступны, но не мешают обычному сценарию
- очередь и модерация не валят room runtime

---

## Сотрудник

### Обязательные сценарии
- войти
- открыть `Общий контур`
- отправить сообщение
- открыть `Голосовой контур`
- войти в голос
- поднять руку
- открыть `Зал собраний`
- открыть профиль и настройки

### Критерий приёмки
- сотрудник проходит базовый рабочий день без технического шума
- shell понятен без обучения

---

## Приглашённый / внешний участник

### Обязательные сценарии
- открыть invitation flow
- принять приглашение
- войти только в разрешённый сценарий

### Критерий приёмки
- invitation flow не выглядит тестовым
- внешний участник не получает лишних прав

---

## Заблокированный

### Обязательные сценарии
- попытка входа
- отображение в admin center
- сохранение истории и аудита

### Критерий приёмки
- blocked user не попадает в активный runtime
- учётная запись сохраняется для контроля и истории

---

## Общий критерий по ролям

Приёмка считается пройденной, если каждая роль проходит свой минимальный сценарий без:
- пустого shell
- критического 500
- распада room runtime
- потери room-based логики
- возврата к messenger-first UX

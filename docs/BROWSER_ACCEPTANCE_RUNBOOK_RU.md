# Browser acceptance runbook — room-based V17

## Цель

Подтвердить не только server-side runtime, но и реальный пользовательский сценарий на живом домене `https://ai.voice.oboron-it.ru`.

## Под кем проверять

- супер-администратор
- руководитель / ведущий
- сотрудник

## Подготовка

1. Открыть продукт в актуальном Chromium-браузере.
2. Проверить, что HTTPS зелёный.
3. Подготовить микрофон и разрешения браузера.
4. Открыть отдельное окно / профиль браузера под вторым пользователем.

## Сценарий 1. Вход и shell

### Шаги
- войти под администратором
- убедиться, что shell открылся без пустого экрана
- проверить левую навигацию
- проверить список комнат
- открыть admin center

### Критерий приёмки
- shell не пустой
- комнаты видны
- admin center открывается
- нет критических 500 на первом экране

## Сценарий 2. Текстовая комната

### Шаги
- открыть `Общий контур`
- проверить список участников
- отправить сообщение
- обновить страницу
- убедиться, что сообщение осталось
- открыть сообщения повторно

### Критерий приёмки
- комната открывается
- сообщение уходит и читается после reload
- справа виден рабочий room context

## Сценарий 3. Голосовая комната

### Шаги
- открыть `Голосовой контур`
- нажать `Войти в голос`
- разрешить микрофон
- проверить локальное состояние участника
- под вторым пользователем войти в ту же комнату
- проверить, что участники видят друг друга
- проверить mute / unmute
- проверить hand raise
- проверить выход из голоса

### Критерий приёмки
- браузерный вход в голос проходит
- участники видят друг друга в комнате
- состояния меняются без поломки UI
- выход из голоса не ломает room state

## Сценарий 4. Комната для собраний

### Шаги
- открыть `Зал собраний`
- проверить состав участников
- проверить ведущего
- открыть meeting room
- выполнить базовые действия ведущего
- проверить журнал / статус / итог

### Критерий приёмки
- meeting room открывается
- основные элементы собрания читаемы
- действия ведущего не ломают room runtime

## Сценарий 5. Управляемый вход / модерация

### Шаги
- включить вход по запросу
- под вторым пользователем отправить заявку
- одобрить заявку модератором
- повторить на отклонение
- вызвать пользователя в комнату
- при необходимости переместить пользователя

### Критерий приёмки
- очередь заявок работает
- модераторские действия не дают критического сбоя
- summon / move user работают по сценарной логике

## Сценарий 6. Админка

### Шаги
- открыть users / rooms / departments / invitations / sessions / system / audit
- проверить, что overview не падает целиком
- проверить, что данные загружаются хотя бы в базовом виде
- проверить, что архив не мешает обычному режиму

### Критерий приёмки
- админские разделы открываются
- один проблемный widget не валит весь экран
- данные не выглядят как тестовый мусор

## Сценарий 7. После acceptance

### Если всё зелёное
- зафиксировать статус в `docs/EXECUTION_LEDGER_RU.md`
- поднять процент voice / meetings runtime
- перейти в P1 UI cleanup

### Если найден новый P0
- зафиксировать endpoint / роль / экран / шаг воспроизведения
- дописать это в `docs/EXECUTION_LEDGER_RU.md`
- чинить только точечно, без смены baseline и без нового product pivot

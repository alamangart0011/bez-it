# Screen execution queue — room-based V17

## Приоритет 1

### 1. Shell
Почему сейчас:
- это первый экран после логина
- именно здесь пользователь видит пустоту или техно-шум

Что делать:
- убрать debug/service strip
- уплотнить header
- оставить только room tree, рабочий центр и контекст

Готовность после закрытия:
- 46% -> 70%

### 2. Dashboard
Почему сейчас:
- на домене пользователь ждёт полезную информацию именно здесь
- сейчас главный экран ещё не переведён в диспетчерскую

Что делать:
- показать активные комнаты
- показать голосовые сейчас
- показать собрания
- показать заявки / инциденты / быстрые переходы

Готовность после закрытия:
- 30% -> 75%

### 3. Voice room
Почему сейчас:
- это главный продуктовый модуль после shell
- browser acceptance упирается именно сюда

Что делать:
- compact mode
- one-click join
- participants first
- operator actions only on second level

Готовность после закрытия:
- 50% -> 82%

## Приоритет 2

### 4. Text room
Почему потом:
- runtime уже живой
- требуется именно визуальная полировка

Что делать:
- composer вниз
- actions в hover/menu
- search в header/right panel

Готовность после закрытия:
- 70% -> 90%

### 5. Meeting room
Почему потом:
- сначала надо снять browser voice acceptance
- затем перевести meeting в сценарный вид

Что делать:
- tab model
- ведущий / участники / журнал / итог

Готовность после закрытия:
- 52% -> 80%

### 6. Admin overview
Почему потом:
- должен остаться после стабилизации shell/dashboard

Что делать:
- диспетчерская метрик
- graceful degradation
- быстрые переходы

Готовность после закрытия:
- 55% -> 82%

## Приоритет 3

### 7. Admin users / rooms / departments / invitations / sessions / system / audit
Почему третьим слоем:
- эти экраны важны, но продукт сперва должен стать сильным в shell/room/voice

Что делать:
- перевести в operational panels
- убрать длинные формы
- archive/debug только по фильтру

Готовность после закрытия:
- 50% -> 84%

### 8. Profile and settings
Почему третьим слоем:
- не P0 при живом runtime
- но сильно влияют на ощущение качества

Что делать:
- completion state
- compact groups
- без пустых input как черновика

Готовность после закрытия:
- 45% -> 78%

## Приоритет 4

### 9. Mobile minimum / PWA
Почему последним из продуктовых экранов:
- сначала desktop room-based контур должен стать визуально и сценарно чистым

Что делать:
- drawer
- bottom sheet
- sticky voice dock
- installable PWA

Готовность после закрытия:
- 20% -> 72%

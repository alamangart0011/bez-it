# Правила принятия решений

## Главный принцип
Если есть конфликт между старым архивом, старым чатом и текущим GitHub, главным считать GitHub.

## Активный канон
- room-based V17 baseline
- один baseline
- один deploy path
- один shell
- один admin center

## Запрещено
- возвращать messenger-first как active UI
- плодить новые параллельные активные ветки
- считать старые архивы равноправными GitHub
- делать пустые UI-экраны и пустые действия

## Приоритет действий
1. Сначала подтвердить P0 runtime и schema parity
2. Потом cleanup shell и UX
3. Потом mobile/PWA и branding
4. Только после этого расширять scope

## Приоритет чтения
1. Корневые bootstrap-файлы
2. deploy и SQL
3. backend runtime
4. frontend runtime
5. reference-архивы только при нехватке данных

## Правило для нового чата
Новый чат должен сначала дать краткий status по репозиторию, а не начинать новый анализ с нуля.
